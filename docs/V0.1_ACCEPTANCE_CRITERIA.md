# v0.1 Acceptance Criteria

Status: M0 Revision Round 2 release contract. All criteria are mandatory unless
explicitly marked otherwise. Bracketed milestones identify implementation
ownership, not permission to begin a closed milestone.

## Foundation, packaging, and operation

- **AC-001 [M0] — Locked clean install:** On Python 3.12,
  `uv lock --check` and `uv sync --locked --dev` succeed without changing
  `uv.lock`; the installed `smr` package imports outside `src/`.
- **AC-002 [M0] — Wheel identity:** The built wheel installs in an isolated,
  no-project environment; distribution metadata version equals
  `smr.__version__`; installed `smr version --short` prints that version.
- **AC-003 [M0] — Core quality gates:** Ruff format/lint, configured strict mypy,
  foundation tests, coverage gate, package build, isolated-wheel import, and
  installed-wheel CLI smoke test pass in CI.
- **AC-004 [M0] — Measured platform claim:** M0 CI claims support only for
  `ubuntu-latest` with Python 3.12. Additional operating systems/interpreters are
  supported only after equivalent CI jobs pass.
- **AC-005 [v0.1] — Local operation:** Capture, confirmation, deterministic
  validation, SQLite persistence, statistics, and export work with networking
  disabled and without an account.

## Drafts, confirmed records, and lifecycle

- **AC-010 [M1] — Explicit scalar confirmation:** Manual input first creates a
  `MeasurementDraft`. A `Measurement` exists only after a user confirmation
  targets the exact scalar candidate ID and revision; no constructor/default
  silently confirms it.
- **AC-011 [M1] — Complete scalar:** A confirmed scalar contains quantity,
  original lexical value/unit, parsed representation, optional canonical result,
  physical dimension, timestamps, source, confirmation, validation, lifecycle,
  provenance, and optional metadata without conflation.
- **AC-012 [M1] — Lexical preservation:** Inputs such as `1.5500e3` and `µm`
  remain exactly recoverable after parse/normalize/validation. For files/arrays,
  raw source/payload, reference/digest, and mapping remain authoritative.
- **AC-013 [M1] — Candidate revision separation:** Source, original candidate,
  corrected candidate, parser confidence, and confirmation target are
  independently inspectable. Confirmation of revision N never confirms N+1.
- **AC-014 [M1] — No invented context:** Omitted sample, instrument, condition,
  unit, and uncertainty remain absent and produce specified pending/error states
  where required.
- **AC-015 [M1] — Orthogonal states:** Validation is exactly `pending`, `valid`,
  or `invalid`; lifecycle is `active` or `superseded`. A valid record can be
  superseded and remain historically valid.
- **AC-016 [M2] — Non-destructive supersession:** Correcting a persisted record
  creates a new confirmed record and supersession lineage without modifying the
  earlier source, confirmation, normalization, or validation report.

## Units, dimensions, and representations

- **AC-020 [M1] — Linear normalization:** All M1 linear cases in
  `tests/UNIT_VALIDATION_MATRIX.md` produce specified canonical values/units
  within declared tolerances.
- **AC-021 [M1] — Dimensional rejection:** A unit incompatible with the selected
  quantity creates `unit.dimension_mismatch`, no successful canonical result,
  and validation cannot be `valid`.
- **AC-022 [M1] — Missing/ambiguous units:** Missing required units and forbidden
  aliases remain pending/invalid with field-specific, actionable issues until the
  user resolves them.
- **AC-023 [M1] — Temperature semantics:** Temperature points and intervals use
  separate quantity definitions/policies and cannot be silently interchanged.
- **AC-024 [M1] — dBm semantics:** Absolute logarithmic power is referenced to
  1 mW, uses the explicit `log_absolute_power_dbm` policy, and records that
  selected policy; generic linear conversion is forbidden.
- **AC-025 [M1] — dB loss semantics:** Optical loss is dimensionless but uses the
  explicit POWER-ratio relation `10 * log10(P_in / P_out)`. It is never converted
  to watts or treated as an unspecified amplitude ratio.
- **AC-026 [M1] — Determinism:** Repeated validation of the same
  schema/definition/registry/policy-versioned input produces equivalent canonical
  results, stable issue codes, and validation state.

## Series

- **AC-030 [M1] — Series candidate:** CSV/array parsing creates a
  `ParsedSeriesCandidate` containing raw source, mapping, coordinate/data
  candidates, diagnostics, parser version, ID, and revision.
- **AC-031 [M1] — Batch confirmation:** One explicit user confirmation targeting
  the exact series candidate revision may create a `MeasurementSeries`; per-row
  confirmation is not required.
- **AC-032 [M1] — Named dimensions:** A confirmed series validates shapes and
  preserves coordinate order, quantity IDs, units, and dimensions. Index
  coordinates such as repeat are explicitly non-physical and need no quantity.
- **AC-033 [M1] — Array normalization:** Homogeneous compatible arrays normalize
  element-wise without altering their raw array/source.
- **AC-034 [M1] — Invalid arrays:** Shape mismatches, disallowed non-finite
  values, mixed/unknown units, and incompatible dimensions create explicit
  issues; elements are not silently discarded.
- **AC-035 [M2] — Reference fixture import:** The WG-17 synthetic CSV imports as
  a `repeat x wavelength` series using the declared mapping, batch confirmation,
  conditions, and equipment; accepted plus rejected rows total 27.

## Persistence, evidence, and interchange

- **AC-040 [M2] — SQLite record fidelity:** Save/load is lossless for normative
  record fields, both state axes, confirmation target, validation, and scientific
  provenance. Writes/migrations are transactional and versioned.
- **AC-041 [M2] — External evidence retention:** SQLite ingestion never implies
  external raw evidence may be discarded; embedded payloads or retained
  references/digests and mappings survive round trips and missing-file states.
- **AC-042 [M2] — CSV import diagnostics:** Import uses explicit mapping and
  reports source row/index plus reason for every rejection; accepted plus
  rejected counts equal input rows.
- **AC-043 [M2] — Lossless JSON:** JSON validates against its versioned SMR
  record schema and reconstructs scalar/series records without losing source,
  confirmation, states, or scientific provenance.
- **AC-044 [M2] — CSV export contract:** CSV is a documented projection and
  emits/links a sidecar when needed to prevent context loss.
- **AC-045 [M2] — Scientific Python:** NumPy, pandas, and xarray conversions
  preserve numeric values, shapes/indexes/dimensions, coordinate names, units,
  and quantity IDs where representable.
- **AC-046 [M2] — MATLAB:** A `.mat` file loads with SciPy and contains expected
  arrays, coordinates, units, and essential reference-fixture metadata.
- **AC-047 [M2] — Export immutability:** CSV/JSON/MAT export creates a separate
  manifest/activity record with input/output digests and does not mutate a
  scientific record or append scientific provenance merely for file output.

## Statistics and uncertainty language

- **AC-050 [M3] — Reference statistics:** Mean, sample variance, sample standard
  deviation (`ddof=1`), and SEM match independently specified reference values
  within tolerance and carry compatible units.
- **AC-051 [M3] — Edge cases:** Empty and one-value series return explicit
  insufficient-data outcomes where `n >= 2` is required; NaN is not silently
  presented as a valid result.
- **AC-052 [M3] — No uncertainty conflation:** Descriptive statistics and SEM
  retain those labels. Type A, Type B, combined, expanded, and measurement
  uncertainty require declared evaluation inputs and assumptions.
- **AC-053 [M3] — Outlier provenance:** Default statistics include all confirmed
  values. Exclusion requires a user-authored derived series recording filter,
  reason, inputs, and excluded IDs.
- **AC-054 [post-v0.1] — Confidence intervals:** Deferred until a separate
  contract defines method, assumptions, degrees of freedom, edge cases, unit
  behavior, and deterministic tests.

## User interfaces

- **AC-060 [M2/M3] — CLI workflow:** Documented commands create drafts, confirm
  targeted candidates, validate, import the reference CSV, list/show records,
  calculate supported statistics, and export with non-zero exits on failure.
- **AC-061 [M4] — Desktop workflow:** A user completes capture -> preview ->
  explicit confirmation -> deterministic validation -> metadata/save -> view/
  statistics -> export, with pending/errors visible before persistence.
- **AC-062 [M1/M4] — Actionable errors:** User-visible issues identify field,
  observed input, violated rule, and resolution without overwriting input.

## Release evidence

- **AC-070 [v0.1] — Reproducible evidence:** CI records interpreter, operating
  system, unchanged dependency lock, and passing gates for every platform claimed
  as supported.
- **AC-071 [all] — Scientific regression policy:** Every corrected scientific
  defect has a deterministic regression test linked to its issue.
- **AC-072 [v0.1] — Documentation:** Quick start, schema/version notes, CLI usage,
  fixture explanation, limitations, privacy, security, and contribution guidance
  match the release.
- **AC-073 [v0.1] — License review:** Project files remain Apache-2.0 and runtime
  dependencies have recorded license compatibility review with no known conflict.
- **AC-074 [v0.1] — Critical-defect gate:** No unresolved defect is known to
  silently corrupt, change, lose, or materially misrepresent scientific data.
